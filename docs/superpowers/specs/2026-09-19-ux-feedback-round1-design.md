## 2. 貼り付けの不足列

`Courts.parsePasteRows(text, techniques, defaults)` に第 3 引数 `defaults = { court }` を足す。

- 列が足りない行（名前だけ、名前とコートだけ、…）はエラーにしない。無い列は 性別＝男子・新人＝なし・技＝空
- `cols[1]`（コート）が空のときは `defaults.court` を入れる。`defaults.court` も空なら従来どおり `ok: false`「コートがありません」
- コート名の検証（`-` を含まない・`未分類` でない・32 文字以内）は補った値にも掛ける
- 引数省略時（`defaults` 無し）は従来と同じ動き（既存テストを壊さない）

貼り付けダイアログ（`desk-players.js` の `openPasteDialog`）:

- テキストエリアの上に「コートが空の行に使うコート」のセレクトを置く。既存コート（`Courts.listFrom(ctx.players)`、`未分類` は除く）＋「新しいコート…」（手入力）。初期値は既存コートの先頭、無ければ空（そのときは空欄の行が赤くなる）
- プレビューは `defaults.court` を渡して描く。セレクトを変えたらプレビューを描き直す
- 補ったコートはプレビューの該当セルに薄い色で出す（貼った値と区別）
- ヘルプの「（d）PC の表に打ち込む・Excel から貼り付ける」に「名前だけでも登録できる。コートが空の行はダイアログのコートが使われる」を足す

## 4. 見出しのフィルタ（PC 選手表）

チップの帯（`.desk-players-bar` のコート・性別・巡・新人・技未入力のチップ）と名前の検索欄を撤去し、見出しに寄せる。

| 列 | 見出しの ▼ で開くもの |
|---|---|
| 巡 | チェック式（一巡目／二巡目。`Courts.roundsOf`） |
| 名前 | 検索欄（部分一致。IME は `compositionend` で確定。既存の正規化 `Courts.normalizeName` を使う） |
| コート | チェック式（`Courts.listFrom`、`未分類` を含む） |
| 性別 | チェック式（男子／女子） |
| 新人 | チェック式（新人のみ／新人以外） |
| 技1〜3 | 「技が未入力の行だけ」のチェック 1 つ（3 列で共通。どの列の ▼ から開いても同じ） |
| No.・得点・⋯ | ▼ なし |

- ▼ は見出しの文字の右に小さく置く。押すと見出しの直下に小さなポップオーバー（`position: absolute`、外側クリックと Esc で閉じる。開けるのは同時に 1 つ）
- チェック式は「すべて」の状態が既定。1 つでも外すと絞り込み。ポップオーバーに「すべて選択」「解除」
- 絞り込み中の列は ▼ を塗りつぶし（`▼` → 色付き）、見出しの背景を薄く色付け
- 表の上の行（今のチップの帯の位置）に「表示 n / N 名」と、絞り込み中だけ「絞り込みを解除」ボタン
- 並べ替えは今までどおり見出しの文字クリック（▼ のクリックとは分ける。▼ は `stopPropagation`）
- 状態は今の `filter`（`Courts.defaultFilter()` の形）をそのまま使う。**チェック式のうち複数選択が要るのはコートだけ**なので、`filter.court` を文字列から配列にする（`''` または空配列＝すべて）。`Courts.applyFilter` をそれに合わせ、既存テストは「文字列 1 つ」も引き続き通す（後方互換）。巡・性別・新人は既存の 3 値（すべて／A／B）のまま
- スマホの選手タブは触らない（チップのまま）

## 5. 採点画面のボタン配置

`scoring.html` / `style.css` / `app.js` のイベント配線は変えず、DOM の位置と CSS を変える。

```
┌──────────────────────────────────────────────────────┐
│           Aコート   A-男子-1-3   山田 太郎              │  ← .player-nav（ボタン無し。中央揃え）
├──────────────────────────────────────────────────────┤
│  技 │ 初太刀 │ 二ノ太刀 │ 三ノ太刀 │ 四ノ太刀 │ 補正点 │ 得点 │  ← 採点表（そのまま）
│  …                                                   │
├──────────────────────────────────────────────────────┤
│  全体補正点 [  ]   備考 [            ]                 │  ← .adjust-bar（そのまま）
├──────────────────────────────────────────────────────┤
│  ▶ 開始   ■ 停止   ↺ リセット                 05:00   │  ← .timer-bar（.action-block の 1 段目）
│  ◀ 前の選手  形成功  失敗  確定  合計 42点  次の選手 ▶ │  ← .action-bar（2 段目）
├──────────────────────────────────────────────────────┤
│  CSVエクスポート  HTML保存  🌙 ダーク                  │  ← .toolbar（そのまま）
└──────────────────────────────────────────────────────┘
```

- `btnPrev` `btnNext` を `.player-nav` から `.action-bar` へ移す。`.timer-bar` を `.adjust-bar` の下、`.action-bar` の直上へ移し、2 つを `.action-block` で囲んで 1 つの区画に見せる（枠と背景）
- `.action-bar` の並び: `btnPrev` / `btnAllSuccess` / `btnAllFail` / `btnConfirm` / `totalScoreDisplay` / `btnNext`。前後の選手は `.nav-btn` の見た目のまま
- 768px で 1 段に収まる幅にする（各ボタン 44px 以上。合計の表示は今の大きさを保つ）。収まらなければ前後の選手ボタンの文言を「◀ 前」「次 ▶」に短くする
- `.player-nav` は選手名だけになるので中央揃え、文字を少し大きく
- キーボードやタイマーの動作、`app.js` の `getElementById` は id が同じなので変更不要。`style.css` の `.player-nav .nav-btn` のセレクタは `.action-bar .nav-btn` に直す
- スマホ幅は対象外（採点画面は 768px 以上の前提のまま）
- ヘルプ `help.html` の「採点画面の見方」の説明とスクリーンショット（`help/img/` の採点画面の画像）を新しい配置で撮り直す。撮り方は前回と同じ CDP（`Emulation.setDeviceMetricsOverride` で幅 768 または 1024、`Page.captureScreenshot`）。画像の差し替えは同じファイル名で上書き

## テスト（`test.html`）

1. `parsePasteRows`: 名前だけの行が `defaults.court` で `ok: true`（コート・性別＝男子・新人＝なし・技＝空）、`defaults` 無しなら従来どおり「コートがありません」、補ったコートにも名前の検証が掛かる（`defaults.court` が `A-1` なら `ok: false`）
2. `Courts.applyFilter`: `filter.court` が配列のとき複数コートが残る、空配列と `''` は全件、文字列 1 つは従来どおり
3. 既存テストがすべて通る（現在 853）

## 手動確認

- PC 選手表・スマホ選手タブ・採点画面の一覧で全列が中央揃え（ライト／ダーク）
- 貼り付けで名前だけ 3 行 → コートの既定値で登録される。コートのセレクトを変えるとプレビューが変わる
- 見出しの ▼ で絞り込み、複数コートの選択、「表示 n / N 名」、「絞り込みを解除」、Esc と外側クリックで閉じる、並べ替えと干渉しない
- メニュー名が PC・スマホ・ヘルプで揃う。375px で下タブが折り返さない
- 採点画面 768px で 2 段の操作区画が収まり、前後の選手・タイマー・形成功・失敗・確定・合計がすべて動く。1024px でも崩れない
