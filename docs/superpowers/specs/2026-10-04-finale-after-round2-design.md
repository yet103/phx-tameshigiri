## 0. 合意した仕組み（2026-10-04 ユーザーと合意。「おすすめで一旦実装」）

1. **試技は全員が一巡目と二巡目を 1 回ずつ。** 追加の試技は無い。順位は **一巡目＋二巡目 の合計**（今のまま）。
2. **二巡目の試技順は最初に決めたまま変えない**（コート×性別ごとに一巡目の確定得点の低い順。今のまま）。
3. **斬る見せ場＝最終組。** 一巡目の一般男子上位 4 名（4 位同点は全員。0 点は除く）を A コート（先頭コート）の二巡目の最後にまとめて斬らせる。今の `finalist` の仕組みをそのまま使う。これは「選考」ではなく**順番の演出**なので、呼び名を「決戦」→**「最終組」**に変える。
4. **結果の見せ場＝ベスト4。** 合計（一巡目＋確定済みの二巡目）の一般男子上位 4 名（同点は全員。0 点以下は除く）。二巡目の途中は**「暫定ベスト4」**として点が入るたびに動き、**残り人数**（二巡目が未確定の一般男子）を添える。全員が斬り終えると**「ベスト4」**として確定する。最終組の 4 名とは別の概念（一致しないことがあるのは当然）。
5. **発表モードに「ベスト4 発表」**を足す。4 位 → 3 位 → 2 位 → 1 位の順にタップで 1 人ずつ出すカウントダウン（名前・合計・一巡目・二巡目）。今の「決戦」モードは**ベスト4 のモードに置き換える**（D1）。
6. **旧データは影響なし**（仕組みは同じ。呼び名と表示だけ）。データの形・状態の内部名・CSV の列名は変えない。

## 1. 用語

| 語 | 意味 | 判定 |
|---|---|---|
| **最終組** | 一巡目を終えた時点の一般男子の一巡目上位 4 名（同点は全員・0 点除外）。A コートの二巡目の最後にまとめて斬る。**順番の演出** | 二巡目の行の `finalist === true`（`EventStatus.finalists`）。選考は `EventStatus.pickFinalists`（変えない） |
| **ベスト4** | 一般男子の合計（一巡目＋二巡目）の上位 4 名（同点は全員・合計 0 点以下は除く）。**結果の見せ場** | `EventStatus.best4Standings`（2.3）。`final: true` のとき |
| **暫定ベスト4** | ベスト4 が確定する前（二巡目が未確定の一般男子が残っている）の同じ表。点が入るたびに動く | `best4Standings(...).final === false` |
| **残り** | 二巡目の行が未確定の一般男子の人数 | `best4Standings(...).remaining` |
| **一般男子** | `isFemale !== true` の選手（新人を含む）。順位の「一般男子」と同じ | — |
| **合計** | 一巡目の確定得点＋二巡目の確定得点。一巡目の行ごとにまとめる（順位と同じまとめ方。2.2） | `EventStatus.playerTotals` |
| **先頭コート** | 選手のいるコートの文字列昇順の先頭（通常 A）。今の `EventStatus.firstCourt` | 変えない |

「決戦」という語は**画面から無くす**。残すのは内部名（状態 `round2_final`、項目 `finalist`、関数名 `finalists` / `finaleCourt` / `computeFinale`、応答の `finale`、CSS の `finale` を含むクラス名、`id="btnModeFinale"` など）と、CSV の列名「決戦」（互換のため。help の CSV の説明は「決戦（最終組の印）」と補う）だけ。

## 2. データと共通部品（`status.js`）

### 2.1 データの形は変えない

- 選手の行・`finalist` の印・`sourcePlayerId`・`order`・状態（`round2_final` を含む 8 状態）・遷移表・CSV の 23 列（列名「決戦」も）・バンドル・大会のコピー・採点の鍵・live・履歴の形はすべて今のまま。
- 旧データの移行は無い。

### 2.2 合計のまとめ方を共通化する（`EventStatus.playerTotals(players, opts)`）

`server/index.js` の `computeRanking` が持っていた「一巡目の行ごとに合算」を `status.js` に移し、順位（`computeRanking`）と ベスト4（`best4Standings`）が**同じまとめ方**を使う。「順位表の一般男子の上位 4 ＝ ベスト4」を構造で保証するため。

- まとめ方（網羅検証 M1 の規則をそのまま移す）: 一巡目の行は自分の `id`（無ければ行ごと）、二巡目以降の行は `sourcePlayerId` の組、それも無ければ同じ氏名・同じ性別の一巡目の組（無ければ氏名＋性別の組）。氏名・性別・新人は組の代表（一巡目の行）から。代表の氏名が空なら組の中の最初の空でない氏名。**氏名の無い組は返さない**（順位と同じ）。
- 数える得点: `opts.countAll`（status を持たない旧データ。サーバーの `countsAllScores`）なら全行の `score`、それ以外は確定済みの行の `score`。
- 戻り値（組の並びは最初に現れた順）:

```
[{ key, name, isFemale, isNewFace,
   r1,        // 一巡目の行の得点の和
   r2,        // 二巡目以降の行の得点の和（確定済みだけ）
   total,     // r1 + r2（computeRanking の score と同じ値）
   r2Rows,    // 二巡目以降の行の数
   r2Done }]  // r2Rows > 0 かつ その行がすべて確定済み（countAll なら確定済みか採点済み）
```

### 2.3 ベスト4（`EventStatus.best4Standings(players, opts)`）

```
opts: { countAll?: boolean,   // 旧データ（status を持たない大会）。サーバーは countsAllScores(event)
        status?: string }     // 大会の状態（EventStatus.of(event)）。final / archived なら確定扱い
戻り値: { final: boolean, remaining: number,
          rows: [{ name, total, r1, r2, rank }] }
```

- **rows**: `playerTotals` の一般男子（`isFemale !== true`）のうち `total > 0` を、合計の降順・同点は氏名順（`localeCompare(..., 'ja')`。順位と同じ）に並べ、同点同順位（1, 1, 3）で `rank <= 4`（`BEST4_COUNT`）の全員。`r2` は二巡目を終えた人（`r2Done`）は二巡目の得点、まだの人は **`null`**（画面は「—」）。`total` は確定済みの分だけの合計（まだの人は一巡目だけ）。
  - 0 点以下を除くのは最終組の選考（`pickFinalists` の `> 0`）にそろえたもの。順位は 0 点の人を消さないので、rows は「順位の一般男子のうち score > 0 かつ rank <= 4」と**同じ行・同じ順位**になる（テストで固定）。
- **remaining**: 二巡目の行が 1 つでもある大会では「二巡目の行があって `r2Done` でない一般男子の組」の数（二巡目の行が無い組＝コート未分類などで二巡目を作られなかった人は数えない）。二巡目の行が 1 つも無い大会（一巡目の途中など）は一般男子の組の数（全員がまだ）。
- **final**: `status` が `final` / `archived`（`isLocked`）なら `true`（結果を確定した＝二巡目を行わずに最終結果にした大会も含む）。それ以外は「二巡目の行がある かつ remaining が 0」。
  - 画面は `final` が `false` のときだけ「暫定」と残り人数を出す。`final` が `true` なら remaining は出さない（二巡目を行わずに最終結果にした大会では remaining が 0 でないことがある）。
- 状態に依らずいつでも計算できる。どの状態で見せるかは画面が決める（3 章）。
- 画面（PC・スマホの運営）は選手の行を持っているので、**API を待たずに** `EventStatus.best4Standings(players, { status: st, countAll: typeof event.status !== 'string' })` で計算してよい。発表・共有・配信ボードは ranking API の `best4`（2.6）を使う。

### 2.6 ranking API（`server/index.js` の `computeRanking`）

`GET /api/events/:id/ranking` と `GET /api/links/:token/ranking`（どちらも `computeRanking`）の応答に `best4` を足す。既存の `rankings`・`finale`（最終組の表）はそのまま。

```
{ event: { name, date, venue, updatedAt },
  rankings: { male: [{ rank, name, score }], female: [...], newFace: [...] },
  finale: { court, status, rows: [{ name, order, r1, r2, total, scored, rank }] } | null,   // 最終組の表（変えない）
  best4: { final: boolean, remaining: number,
           rows: [{ name, total, r1, r2, rank }] } }                                        // 新規。常にある（null にしない）
```

- `best4 = EventStatus.best4Standings(players, { countAll: countsAllScores(event), status: EventStatus.of(event) })`。
- `computeRanking` の合算は `EventStatus.playerTotals` に置き換える（2.2。出力は変えない）。
- 共有リンクから無認証で読まれるので、`best4.rows` にも ○× の生データ・order・id は入れない（name・total・r1・r2・rank だけ）。
