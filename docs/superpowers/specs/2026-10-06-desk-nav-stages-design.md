# PC 運営の段階表示の一本化（左メニューを工程順に。案 B'）

日付: 2026-10-06
ユーザー要望: 「上部のステータス遷移と、左のメニューが冗長バラバラ。UX 観点で提案ください」→ 案 A（帯に一本化）・B（左メニューを工程順）・C（名前だけ揃える）を提示 → 「B がわかりやすいのでは」→ 折衷案 B' で決定。

## 1. 決めたこと

- **左メニューが工程表を兼ねる**。「準備／一巡目／形登録／二巡目／結果」の 5 つの区切り（段階）を入れ、各段階の下にその段階で使う区画を置く。
  - 準備: 基本情報・技得点表・選手登録
  - 一巡目: 試合進行
  - 形登録: 二巡目の形（従来の「二巡目の形登録」。これまで二巡目準備のときだけ出していたが、段階として常に出す。他の段階で開くと従来どおり「形を直せるのは…」の案内）
  - 二巡目: 試合進行（一巡目と同じ区画。区画は 1 つで、メニューの項目が 2 つ）
  - 結果: 結果確認
- 今の段階の区切りに「◀ いまここ」の印（金）、終えた段階は薄い字、まだの段階は通常。いま開いている区画の項目は従来どおり強調（`.on`）。「試合進行」は 2 か所にあるので、今の段階に近い方（段階が一巡目以前なら一巡目の下、二巡目以降なら二巡目の下）だけ強調する。
- **上の帯は 1 行**。大会名・日付・会場と、右端に「確定 14 / 35」などの件数（`Courts.stageCountText`）。二巡目終了・アーカイブはその前に補足（「二巡目終了　確定 …」）。段階の「● ─ ○」の並びは消す。
- **区画の先頭は操作の 1 行**。「① → ② → ③ → ④」の段の並びは消し、案内文（`stepTodo`）と「戻す」「進める」「二巡目を行わず最終結果へ」のボタンを 1 行に収める（狭ければ折り返す）。二巡目の行の誤りの帯（blockers）はその下に。近道ボタン（形登録へ →／試合進行へ →／結果確認へ →）は案内文の後ろに残す。
- 段階が進んだときの自動移動は従来どおり（試合開始 → 試合進行、一巡目終了 → 形登録、形登録から進める・戻す → 試合進行）。

## 2. 実装

- desk.js: `NAV` を `NAV_GROUPS`（label・states・items）に。`navModel(st, currentTab)` を純粋関数として切り出し（段階の done/now/todo と項目の on）、`renderNav` はそれを描くだけ。`STAGE_GROUPS` は `NAV_GROUPS` の label/states から作る（`stageOf` はそのまま。段の名前は 準備・一巡目・形登録・二巡目・結果）。`buildStage` は件数と補足だけを返し、見出しの行の右端に置く。
- desk-match.js `buildSteps`: 段の並び（`MATCH_STEPS` の描画）をやめる。`MATCH_STEPS` / `matchStepIndex` は test.html が固定しているので関数は残す。
- desk.css: `.desk-nav-group`（段階の見出し。`.now` 金・`.done` 薄い）、`.desk-steps` を flex の 1 行に、`.desk-stage-*` の段の並びのスタイルは削る。
- test.html: `stageOf` の段の名前を更新、`navModel` のテストを足す。
- help.html: 状態バー・工程表の説明を B' に合わせる。

## 3. 試さなかった案

- 案 A（帯に段階と操作を一本化）: どの区画からでも進められるが、帯が高くなる。ユーザーは B の分かりやすさを優先。
- 案 C（名前だけ揃える）: 冗長さが残る。
