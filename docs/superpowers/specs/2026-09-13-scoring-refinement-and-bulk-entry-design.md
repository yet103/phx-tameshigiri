# 採点画面の改良（補正点・確定・行操作）と選手の一括登録

**日付**: 2026-09-13
**対象**: phx-tameshigiri（試し斬り採点システム）
**前提となる設計書**: [2026-09-08-mobile-admin-flow-design.md](2026-09-08-mobile-admin-flow-design.md)

採点画面の入力を大会の実態（技ごとの補正、全体補正、備考、確定の合図）に合わせ、
運営画面では名簿の一括投入（テキスト貼り付け・簡易 CSV）と採点画面への導線を足す。

## 決定事項（ブレストで確定）

| 論点 | 決定 |
|---|---|
| 一括登録の入力方法 | **複数行テキスト貼り付け**（1行1人の名前。コート・性別・新人はシート上部で共通指定） |
| CSV インポート | **簡易列（名前,コート,性別,技①,技②,技③,新人）にも対応**。既存9列（エクスポート互換）も引き続き受け付ける |
| 補正点（旧・技術点） | **整数・マイナス可・上限なし**。空欄は 0。既存データの技術点○は +3 と読み替える |
| 確定 | **確定後も編集でき、編集すると確定が解除される**。確定は選手データに保存する |
| スマホでの採点 | **使えるようにする**（`body{min-width:768px}` を外す） |
| 選手一覧の置き場所 | **ページ下部に埋め込む**。トグルで開閉。浮くパネルは廃止 |
| 形（技）の行選択 | **技名セルのタップで選ぶ。選手切替時は1行目を自動選択**。セルをタップした行にも選択が移る |
| 太刀の表記 | **「初太刀・二ノ太刀・三ノ太刀・四ノ太刀」に全画面を統一** |

## T5 データモデル

### 選手オブジェクトに足す項目

| 項目 | 型 | 既定 | 意味 |
|---|---|---|---|
| `adjust` | 整数3要素の配列 | `[0,0,0]` | 採点表の行ごとの補正点。添字は `result` と同じく「空の枠を詰めた表示行」の順（`tech1..3` から空を除いた順） |
| `totalAdjust` | 整数 | `0` | 選手全体の補正点 |
| `note` | 文字列（200文字まで） | `''` | 備考 |
| `confirmed` | 真偽値 | `false` | 確定済みか |

得点の式: **`score = Σ(太刀の配点) + Σ adjust[i] + totalAdjust`**。
これまでどおり採点画面（クライアント）が計算して `score` を送り、サーバーは保存だけする。順位表・発表・共有は `score` をそのまま使うので変更しない。

### 結果文字列 `result` との互換

- 形式は変えない。技ごと5文字（初〜四の太刀 4文字＋5文字目）。`Scoring.canDecode` の判定（長さ＝技数×5、`[01 ]` のみ）もそのまま。
- **新しい保存では5文字目を常に空白にする**（補正点は `adjust` に持つ）。
- **読み替え**: 選手に `adjust` が無い（配列でない）ときだけ、5文字目が `'1'` の技は補正点 3、それ以外は 0 とみなす。`adjust` がある選手は5文字目を見ない。
- **移行のタイミング**: 採点画面は編集した選手だけを保存する（通過しただけでは他端末の値を巻き戻さないため）。したがって旧データの `adjust` への移行は、その選手を採点画面で一度編集したときに起きる。編集するまでは順位表・発表・共有は保存済みの `score` をそのまま使う（通常の旧データでは再計算値と一致する）。
- `Scoring.decodeResult(result, techCount, adjust)` は各行 `{ values: [4つ], adjust: 整数 }` を返す（`techPoint` は廃止）。
- `Scoring.encodeResult(rows)` は `rows[i].values` だけを見て5文字目は空白を書く。
- `Scoring.calcTotalScore(rows, isFemale, totalAdjust)` は上の式で計算する。
- 採点済み判定 `Courts.isScored` / サーバー `isScored`（同じ規則を両側に持つ）: 従来の条件に **`adjust` のいずれかが 0 以外、または `totalAdjust` が 0 以外** を足す。`score > 0` の条件は残す（負の補正で 0 以下になっても `result` か `adjust` で拾える）。

### サーバー

- `PATCH /api/events/:id/players/:playerId` の受理項目に追加:
  - `adjust`: 長さ3の配列で全要素が有限の整数のときだけ受理。それ以外は無視。
  - `totalAdjust`: 有限の整数のときだけ受理。
  - `note`: 文字列のとき受理。前後の空白を落とし、200文字を超える分は切り捨てる。
  - `confirmed`: 真偽値のとき受理。
  - `score`: **負数も受理する**（有限の数なら受理。NaN / Infinity は無視のまま）。
- `GET /api/events/:id/export` の列: `選手名,順番,技1,技2,技3,得点,新人,女子,結果,補正点1,補正点2,補正点3,全体補正,備考,確定`（確定は `○` / 空）。
- `POST /api/events/:id/import` は先頭行で形式を判別する。**実装は T2 の担当**（T5 は import に触らない。同じ関数を2人で編集しないため）:

| 先頭行 | 形式 | 順番 |
|---|---|---|
| 2列目が「コート」 | 簡易7列（T2） | サーバーが採番 |
| それ以外で 9列 | 従来9列 | CSV の値 |
| それ以外で 10列以上 | 拡張15列（補正点・備考・確定つき） | CSV の値 |

  拡張15列では `adjust` / `totalAdjust` は整数として読み、読めなければ 0。`確定` は `○` のとき true。

### クライアントの保存経路

- `Outbox.enqueue` のエントリに `adjust`, `totalAdjust`, `note`, `confirmed` を足す。送信時の PATCH と `applyPending`（画面への反映）でもこの4項目を扱う。既存の未送信エントリ（旧形式）にはこれらが無いので、無いときは触らない。
- `Storage.buildPlayersHtml`（HTML保存）の列は CSV エクスポートと同じ15列にする。
- 採点履歴 `Api.addHistory` の `detail` は「補正点 → n」「二ノ太刀 → 成功」のような表記にする。

## T6 採点画面（index.html / app.js / style.css）

### 採点表

- 見出し: `技 | 初太刀 | 二ノ太刀 | 三ノ太刀 | 四ノ太刀 | 補正点 | 得点`
- 太刀セルの表示: 空 → **「未」**（薄い文字色）、`○` → **「成功」**（`success` クラス）、`×` → **「失敗」**（`fail` クラス）。内部値（`dataset.value`）は従来どおり `''` / `'○'` / `'×'` のまま。打てない太刀（配点 null）はこれまでどおりグレーで空欄。
- タップの順序は従来どおり 未 → 成功 → 失敗 → 未。
- 補正点セル: `<input type="number" step="1" inputmode="numeric">`。0 のときは空欄で表示し、空欄は 0 として扱う。`change` で行得点・合計を更新して保存する。
- 得点列の値: 太刀の配点合計＋その行の補正点。行に何も入っていない（太刀が全部「未」で補正も 0）ときだけ空欄にし、入力があれば 0 や負の数もそのまま表示する（補正で負になる場合を見せるため）。

### 行の選択（ハイライト）

- 技名セルのタップで行を選ぶ。太刀セル・補正点セルをタップしたときもその行が選択される。
- 選手を切り替えたら1行目を選ぶ。技が無い選手は選択なし。
- 選択行は `tr.selected` で背景を強調する（`--row-selected` を theme.css に追加）。
- 技名セルは太字 20px で ①②③ の番号（表示行順）を前置し、選択行の技名セルはアクセント色で塗りつぶす（どの形を採点しているかを一目で分かるように）。
- 選手名の帯は「コートのバッジ（アクセント色、30px）＋ 性別・巡目・番号（小）／選手名（32px 太字）」。スマホ幅では名前の帯をボタンの上に一段で置き、前後ボタンを横いっぱいに広げる。大会未選択・コート不明のときはバッジを出さない。
- 「形成功」: 選択行の打てるセルを**すべて成功**にする（失敗も成功に変わる）。
- 「失敗」: 選択行の**「未」のセルだけ**を失敗にする（成功は触らない）。
- 選択行が無いときは「形を選んでください」と案内して何もしない。

### 全体補正点・備考

- 採点表の下に1段設ける: `全体補正点 [数値入力]　備考 [テキスト入力]`。
- 全体補正点は `change` で合計を更新して保存する。備考は `change`（フォーカスが外れたとき）で保存する。
- 備考の編集では確定を解除しない（得点に影響しないため）。

### 確定

- アクションバーに「確定」ボタンを置く（合計の左）。
- 押すと `confirmed = true` にして保存し、得点列・合計・下部一覧の得点を青（`--score-confirmed`、ライト `#1a56db` / ダーク `#60a5fa`）にする。ボタンは「確定済み」表示（押し込み状態）に変わる。
- 得点に関わる編集（太刀セル・補正点・全体補正点・形成功・失敗）をすると `confirmed = false` にして保存し、色を戻す。
- 技が無い選手、または内訳を復元できない選手（`gridRestorable` が偽で未編集）では確定できない。

### 選手一覧（下部埋め込み）

- 浮くパネル（`.player-list-panel`）を廃止し、ツールバーの下に `<section class="player-list-section">` を置く。見出し行に「選手一覧 ▾ / ▸」のトグルボタン。
- 列は従来どおり `順番 | 選手名 | 技1 | 技2 | 技3 | 得点`。確定済みの選手の得点は青。現在の選手行は従来どおり強調。
- 初期状態: 画面幅 768px 以上なら開、未満なら閉。開閉は `localStorage`（`tmg_player_list_open`）に記憶し、記憶があればそれを優先する。
- ツールバーの「選手一覧」ボタンは廃止し、見出し行のトグルに一本化する。

### スマホ対応

- `style.css` の `body{min-width:768px}` を外す。
- `.score-table-wrap` は横スクロール可（既存）。`.player-nav` / `.timer-bar` / `.action-bar` / `.toolbar` / `.event-bar` は `flex-wrap: wrap` にして折り返す。
- タップ目標は 44px 以上を守る（太刀セルの高さは 44px のまま）。

## T4 技シート（techpicker.js / admin.css）

- シートの並びは上から **タイトル行 → 検索欄 → ヘッダー行 → 一覧**。ヘッダー行は一覧に隣接させ、一覧をスクロールする領域の中に `position: sticky` で置く（外に置くと PC のスクロールバー幅ぶん列がずれる）。
- ヘッダー行は `技名 | 初太刀 | 二ノ太刀 | 三ノ太刀 | 四ノ太刀`。各技の行は同じ列幅で配点を並べる（打てない太刀は `—`）。列は CSS grid（`grid-template-columns: 20px 1fr repeat(4, 48px)`）で揃え、技名は左寄せ、配点の数値は右寄せ（`tabular-nums`）。ヘッダーの太刀名は 11px で1行に収める。
- 検索欄（`<input type="search" placeholder="技名で絞り込み">`）。入力のたびに一覧を絞り込む。IME 変換中（`isComposing`）は再描画せず、`compositionend` でも絞り込む（WebKit は確定後に `input` が来ない）。自動フォーカスはしない（スマホでキーボードが開くのを避ける）。
- 絞り込みは純粋関数 **`TechPicker.filter(techs, query)`** に切り出す: 前後の空白を落とし、空なら全件（複製）。`normalize('NFKC')` と小文字化をしてから技名の部分一致で判定する。
- 「（この枠を空にする）」は検索中も常に先頭に出す。該当が無いときは「該当する技がありません」を出す。
- 既存の `strikesLabel` は残す（テストが参照している）。
- `test.html` に `filter` のテスト（空・部分一致・全角半角・大文字小文字・該当なし・複製）と、シートの DOM テスト（ヘッダー行の位置・検索で絞り込まれる・該当なし表示）を足す。

## T1 選手一括登録（admin-players.js / server）

### サーバー `POST /api/events/:id/players/bulk`

- 入力: `{ court, isFemale, isNewFace, names: [] }`。
- 検証: `court` は `isValidCourt`、`names` は配列で各要素を trim して空を除く。残りが 0 件なら 400。500 件を超えたら 400。
- 1回の読み書きで、`nextOrderNumber` を累積しながら順に採番して `players` に足す（一巡目、技は空）。
- 応答: `201 { success: true, created: n, players: [...] }`。
- 単体追加 API（`POST /players`）は変更しない。

### 画面

- 選手タブの「⋯」メニューに「👥 複数人をまとめて登録」を足す。
- シート「複数人をまとめて登録」: コート（セグメント＋「＋」）、性別（セグメント）、新人（トグル）、名前の複数行入力（`textarea`、1行1人）。入力欄の下に「n 人」を表示する（空行を除いた件数）。
- ボタン: 「閉じる」「登録」。登録時に `confirm('A コート 男子 12 人を登録します。よろしいですか？')` を出し、承諾で bulk API を呼ぶ。成功したらトースト「12 人を登録しました」で閉じて一覧を再読込。失敗したらシートは閉じず入力を残す。
- 通信中は `sheet.lock(true)` とボタン無効化（既存の追加シートと同じ）。await の後は `Admin.currentEventId()` で大会が変わっていないか確認してから DOM に触る。
- コート・性別・新人の部品は `buildPlayerForm` から切り出して共用する（重複実装しない）。

## T2 CSV 簡易列（server import）

- 先頭行の2列目が「コート」なら簡易形式とみなす。列: `名前,コート,性別,技①,技②,技③,新人`。
  - 名前: 空なら行を飛ばす。
  - コート: `isValidCourt` を通す。不正なら 400 で「n 行目のコート名が不正です」。
  - 性別: `女` / `女子` / `○` / `F` なら女子、それ以外は男子。
  - 技①②③: そのまま文字列。
  - 新人: `○` / `1` / `はい` / `新人` なら true。
  - 順番: サーバーが（既存＋この CSV で先に読んだ分）から `nextOrderNumber` で一巡目に採番する。
- `replace` / `append` と採点済みガードは従来どおり。
- `test.html` の API テストに簡易形式の読み込み（採番・性別・新人）を足す。画面側の変更は不要（既存の CSV 導線をそのまま使う）。

## T3 進行タブから採点画面へ（admin-round.js / admin.js）

- 見出し行（`round-head`）に「採点画面へ」のリンク（`<a id="btnOpenScoring" class="round-open">`）を置く。「二巡目を生成」のアクセント塗りと並ぶので、こちらはアクセント色の枠線（アウトライン）にする。`<a>` にするのは、同じタブで遷移しつつ長押し・中クリック・キーボード操作も効くようにするため。

- コート絞り込みチップを切り替えたら `href` も更新する。
- 同じタブで遷移する（コート端末で運営画面を開いた後に採点へ戻る用途）。

| 発表モード・共有ページ | 常に**黒金**（`share.js` は端末の設定に関わらず `data-theme="dark"` に固定） |

- 変数は `theme.css` に集約する。帯の色（`--band-*`）と金・朱（`--gold` / `--gold-light` / `--gold-deep` / `--vermilion`）はテーマに依らず同じ値。カードの紙色は `--card-bg`。
- 見出し（選手名・技名・表の見出し・運営画面のタイトル・発表の部門名）は明朝体（`--mincho`）。ポスターの太い明朝に寄せるため **しっぽり明朝 B1 Bold（OFL）を `fonts/` に同梱**し、このサーバーから配信する（JIS X 0208 ＋ ASCII ＋ 丸数字に絞った woff2、約 2.1MB、`font-display: swap`）。同梱外の字や読み込み前は端末の游明朝／ヒラギノ明朝に落ちる。本文はゴシックのまま。
- 成功（緑）・失敗（赤）のセル色は判別しやすさを優先し、ポスターの色には寄せない。
- 各 CSS の「大会トーン」節は上書き専用で、ファイル末尾に置く。
